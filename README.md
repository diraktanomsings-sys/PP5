# PP5 — ระบบรับส่งเอกสารโรงเรียนบ้านคูเมือง

หน้าจอและเมนูเดิมเชื่อมข้อมูลบนเซิร์ฟเวอร์: บัญชีจริง → ครูอัปโหลด Excel/PDF → ผู้ตรวจรับรองหรือส่งกลับ → ผู้บริหารบันทึกลายมือชื่อและล็อกเวอร์ชัน → ดาวน์โหลดจากคลัง

ไม่สร้างบัญชี ข้อมูลบุคลากร หรือเอกสารตัวอย่างในระบบจริง บัญชีแรกสร้างได้ครั้งเดียวด้วยรหัสเปิดใช้งานของผู้ดูแล

## ใช้งานในเครื่อง

ต้องใช้ Node.js 24

1. `npm ci`
2. คัดลอก `.env.example` เป็น `.env.local` ตั้ง `APP_URL=http://localhost:3000` และ `PP5_SETUP_TOKEN` เป็นค่าสุ่มอย่างน้อย 32 ตัวอักษร
3. `npm run dev`
4. เปิด `http://localhost:3000` ผู้ดูแลกรอกรหัสเปิดใช้งาน ชื่อ อีเมล และรหัสผ่านของตนเอง

ฐานข้อมูล PostgreSQL สำหรับพัฒนา (PGlite) และไฟล์อยู่ใน `.pp5-local/` โดยไม่รวมใน Git การรีเฟรช ปิดเบราว์เซอร์ หรือ restart เซิร์ฟเวอร์ไม่ลบข้อมูล ห้ามนำโหมด local ไปใช้บน Vercel ซึ่งไม่มีดิสก์ถาวรแบบนี้

## ตั้งค่าบน Vercel

### เงื่อนไขค่าใช้จ่าย: ฟรีเท่านั้น

ใช้เฉพาะ Neon **Free ($0)** และ Vercel **Hobby** ไม่เปิด Pro/Launch/Scale, paid trial, การคิดเงินตามใช้ หรือเพิ่มวิธีชำระเงิน หากโควตาไม่พอต้องหยุดหรือปรับการใช้งานภายในแผนฟรี ไม่อัปเกรดอัตโนมัติ

แอปรีเฟรชข้อมูลเมื่อเปิดหน้า กดปุ่มรีเฟรช หรือบันทึกรายการ โดยไม่มีการ polling ฐานข้อมูลขณะเปิดหน้าเว็บทิ้งไว้ เพื่อให้ฐานข้อมูลพักการทำงานและประหยัดโควตาฟรี

ตรวจสอบโควตาจาก [Neon Free](https://neon.com/pricing) และ [Vercel Blob Hobby](https://vercel.com/docs/vercel-blob/usage-and-pricing) ก่อนเปิดใช้งานจริงและเมื่อโควตาใกล้เต็ม การใช้แผนฟรีอาจทำให้บริการหยุดชั่วคราวเมื่อเกินโควตา

ยังต้องจัดเตรียมบริการและทดสอบบน deployment จริงก่อนเปิดใช้งานโรงเรียน:

1. เชื่อม PostgreSQL กับโปรเจกต์ PP5 เลือก region ใกล้ผู้ใช้และฐานข้อมูล
2. สร้าง Vercel Blob store ที่ตั้ง **Access: Private** และเชื่อมกับโปรเจกต์ PP5
3. ตั้ง environment variables ฝั่งเซิร์ฟเวอร์:

| ตัวแปร            | ค่า                                                     |
| ----------------- | ------------------------------------------------------- |
| `DATABASE_URL`    | PostgreSQL connection string ของบริการที่เชื่อม         |
| `BLOB_STORE_ID`   | ID ของ private store ที่ Vercel จัดให้                  |
| `APP_URL`         | `https://pp-5-gray.vercel.app` ไม่มี `/` ท้าย           |
| `PP5_SETUP_TOKEN` | ค่าสุ่มอย่างน้อย 32 ตัวอักษร สำหรับสร้างผู้ดูแลครั้งแรก |

อย่าใช้ prefix `VITE_` กับตัวแปรเหล่านี้ อย่า commit `.env.local` หรือใส่ token ในแชท/ซอร์สโค้ด

เชื่อม Blob แบบ OIDC ซึ่ง Vercel จัดการและหมุนเวียนสิทธิ์ให้เอง ไม่ต้องสร้าง `BLOB_READ_WRITE_TOKEN` และไม่ต้องคัดลอก `VERCEL_OIDC_TOKEN` ลงไฟล์หรือแชท การอัปโหลดใช้ presigned URL อายุ 10 นาที จำกัดสิทธิ์เขียนเฉพาะไฟล์ที่บัญชีนั้นจองไว้

4. Deploy source นี้ด้วย `npm run build` ไปยัง Preview ที่ใช้ฐานข้อมูลและ private store สำหรับทดสอบแยกกัน ตั้ง APP_URL ของ Preview ให้ตรงกับโดเมน Preview
5. ตรวจ `/api/pp5?action=health` ว่าพร้อมทำงาน แล้วให้ผู้ดูแลสร้างบัญชีแรกด้วยตนเอง
6. ทดสอบครบทุกบทบาทและสำรองข้อมูลก่อนนำ deployment ขึ้น production
7. หลังสร้างผู้ดูแลแล้ว ให้นำ `PP5_SETUP_TOKEN` ออกจาก environment ระบบจะไม่ยอมสร้างผู้ดูแลคนที่สองผ่าน setup แม้ยังมี token อยู่

หากยังไม่ได้ตั้งบริการครบ API จะตอบ 503 และแสดงข้อความเตรียมเปิดใช้งาน โดยไม่มีการย้อนกลับไปใช้บัญชีตัวอย่าง

## เก็บไฟล์ใน Google Drive ของโรงเรียน

ตัวรับไฟล์ `google-drive/Code.gs` ต้องอยู่ใน Apps Script ของบัญชีโรงเรียนและเผยแพร่แบบเว็บแอปที่ทำงานในนามเจ้าของบัญชี ก่อนใช้ต้องตรวจ `PP5_ORIGIN` และ `PP5_FOLDER_ID` ให้ตรงโรงเรียน รวมทั้งใช้ `google-drive/appsscript.json` เจ้าของต้องอนุญาตสิทธิ์ Drive, การเรียกเซิร์ฟเวอร์ PP5 และอีเมลบัญชีเอง สิทธิ์ Drive ที่ Google ขอเป็นสิทธิ์กว้างทั้ง Drive แม้โค้ดกำหนดให้ใช้เพียงโฟลเดอร์ที่ระบุ หาก Workspace ไม่อนุญาตเว็บแอปแบบ Anyone ให้หยุดและขอแนวทางจากผู้ดูแลโดเมน ไม่เปลี่ยนนโยบายโรงเรียนเอง

ผู้ดูแล PP5 เปิด **คลังเอกสาร → พื้นที่เก็บไฟล์ Google Drive ของโรงเรียน** กรอก URL เว็บแอป `/exec` และรหัสโฟลเดอร์ แล้วตรวจการเชื่อมต่อ ระบบสร้างไฟล์ทดสอบที่ไม่มีข้อมูลนักเรียน อ่านตรวจแฮช และย้ายเฉพาะไฟล์ทดสอบใหม่นั้นลงถังขยะสำเร็จก่อนเปิดใช้ โฟลเดอร์ต้องตั้ง General access เป็น Restricted

คำขอเข้า Apps Script ใช้กุญแจงานสุ่มอายุ 3 นาที ใช้ครั้งเดียว โดยรายละเอียดและไฟล์มาจากเซิร์ฟเวอร์ PP5 ที่กำหนดตายตัว ไม่รับ URL หรือคำสั่งจัดการ Drive จากผู้เรียก ไม่เก็บ Google OAuth token หรือกุญแจถาวรใน PP5 ผู้ใช้ยังต้องผ่านสิทธิ์ PP5 เดิมก่อนอ่านเอกสาร

ไฟล์ Excel/PDF ใหม่ผ่าน private Blob ชั่วคราวเพื่อรองรับอัปโหลดโดยตรง แล้วคัดลอกเข้าโฟลเดอร์โรงเรียนและตรวจ SHA-256 ก่อนยืนยันพร้อมส่ง หลังบันทึกตำแหน่ง Drive จึงคืนพื้นที่ Blob; หากคืนพื้นที่ไม่สำเร็จ ต้นฉบับยังอยู่และต้องตรวจเก็บกวาดภายหลัง ไฟล์เดิมมีปุ่มคัดลอกเข้า Drive โดยเก็บต้นฉบับเดิมไว้ บัญชี รายวิชา สถานะ และประวัติยังอยู่ใน Neon ไม่ย้ายเป็นไฟล์ Drive PDF ฉบับประทับอนุมัติและ ZIP สร้างเมื่อต้องดาวน์โหลดจากต้นฉบับ

ใช้ Apps Script/พื้นที่บัญชีโรงเรียนที่มีอยู่ ไม่เปิด Cloud billing หรืออัปเกรดแผน ขนาดไฟล์ยังจำกัด 25 MB ต่อไฟล์และ ZIP รวม 50 MB; มีโควตา Apps Script, Blob และ Vercel แม้พื้นที่ Drive ยังเหลือ ควรนำร่องด้วยไฟล์จริงของโรงเรียนก่อนเปิดวงกว้าง อย่าย้ายต้นฉบับ PP5 ออกนอกโฟลเดอร์ที่กำหนดหรือแก้เนื้อหาทับ เพราะระบบตรวจตำแหน่งและแฮชทุกครั้ง

## เริ่มต้นข้อมูลโรงเรียน

1. ผู้ดูแลเพิ่มบัญชีครู ผู้ตรวจ และผู้บริหาร ให้แต่ละคนใช้รหัสผ่านเฉพาะตนอย่างน้อย 12 ตัวอักษร
2. เปิดปี/ภาคเรียนและระบุกำหนดส่งเป็นเวลาไทย
3. เพิ่มรายวิชา ห้อง ครูผู้สอน และผู้ตรวจที่เป็นคนละคน
4. ครูเข้าใช้ด้วยอีเมลหรือรหัสบุคลากร เห็นเฉพาะรายวิชาตนเอง
5. อัปโหลด `.xlsx` และ `.pdf` อย่างละหนึ่งไฟล์ ขนาดสูงสุดไฟล์ละ 25 MB แล้วกดยืนยันส่ง
6. ผู้ตรวจที่ได้รับมอบหมายเปิดไฟล์จริง ประเมินทั้งสี่ด้าน และบันทึกข้อเสนอแนะ ถ้าส่งกลับ ครูส่งเวอร์ชันถัดไปได้
7. ผู้บริหารอีกคนบันทึกลายมือชื่อและยืนยันอนุมัติ ระบบล็อกเวอร์ชันและเก็บ SHA-256 ของไฟล์กับหลักฐานอนุมัติ
8. คลังแสดงเอกสารที่ส่งแล้วตามสิทธิ์ เลือกสถานะ ปี เทอม ชั้น และคำค้นได้ ดาวน์โหลด Excel/PDF ฉบับล่าสุดหรือ ZIP ตรงตามรายการที่แสดง สูงสุด 100 รายวิชาและ 50 MB ต่อคำขอ พร้อม `submission.json` และ `approval.json` เฉพาะเล่มที่อนุมัติแล้ว

คลังของครู ผู้ตรวจ และผู้ดูแลเริ่มที่ทุกสถานะที่ส่งแล้ว ส่วนเมนูคลังที่อนุมัติแล้วของผู้บริหารเริ่มที่ `FINAL_LOCKED` การเปิดไฟล์รอตรวจไม่ใช่การอนุมัติ และไม่แสดงใบรับรองหรือรหัสแฮชสมมติ การดาวน์โหลด ZIP ตรวจสิทธิ์ทุก ID และทุกไฟล์อีกครั้งบนเซิร์ฟเวอร์ อ่านไฟล์พร้อมกันไม่เกิน 3 รายการ และส่ง ZIP เป็น stream โดยยังคงจำกัดขนาดรวม การเรียก API เดิมที่ไม่ระบุสถานะยังเลือกเฉพาะเล่มที่อนุมัติแล้ว

ลายมือชื่อบันทึกพร้อมหลักฐานอนุมัติและสร้าง PDF สำเนาที่เพิ่มหน้าแนบท้าย โดยเก็บต้นฉบับเดิมไว้ ไม่ได้ออกใบรับรองจากหน่วยงานรับรองดิจิทัล ไม่มีการตรวจสูตรหรือรับรองคะแนนอัตโนมัติ ผู้ตรวจต้องตรวจจากไฟล์จริง

## การเก็บข้อมูลและสิทธิ์

### ครูเลือกส่งทุกวิชาและ PDF ผลตรวจ

ครูเลือกได้ทุกวิชาที่เปิดรับในภาคเรียนปัจจุบันและยังไม่มีการส่ง แม้เป็นคนละกลุ่มสาระ เมื่อส่งไฟล์คู่สำเร็จครั้งแรก เซิร์ฟเวอร์บันทึกผู้ส่งจริงเป็นครูผู้รับผิดชอบใน transaction เดียวกัน หากครูสองคนส่งพร้อมกัน จะรับงานที่บันทึกก่อน อีกคนส่งทับไม่ได้ เอกสารที่มีผู้ส่งแล้วและไฟล์นักเรียนยังเข้าถึงตามเจ้าของงานและผู้ตรวจเดิม หากผู้ส่งเป็นผู้ตรวจที่เคยมอบหมาย ระบบล้างการมอบหมายผู้ตรวจนั้นและให้แอดมินเลือกคนอื่นเพื่อไม่ให้ตรวจงานตนเอง

ผู้ตรวจเปิด “ส่งกลับแก้ไข” ระบุเหตุผลและเลือก PDF จริงได้ สูงสุด 25 MB การแนบเป็นตัวเลือก ส่งกลับได้เมื่อไฟล์ผ่านการตรวจสอบและบันทึกสำเร็จ ครูผู้ส่งเห็นปุ่มดาวน์โหลดผลตรวจในหน้าติดตามผล พร้อมเก็บ PDF ผลตรวจในประวัติเวอร์ชันเดิมแม้ส่งฉบับแก้ไขแล้ว

### การลบและกู้คืนสำหรับผู้ดูแล

หน้าบุคลากร รายวิชา และภาคเรียนมีส่วน “ลบ / กู้คืนรายการ” พร้อมยืนยันชื่อรายการ การลบย้ายเข้าถังขยะและบันทึก Audit โดยยังเก็บชื่อบุคคล ไฟล์ เวอร์ชัน และหลักฐานอนุมัติไว้สำหรับคลังย้อนหลัง ไม่ลบไฟล์ใน Drive หรือ Blob

ในถังขยะเพิ่ม “ลบถาวร” โดยสรุปจำนวนเอกสาร เวอร์ชัน ไฟล์ และขนาดก่อนพิมพ์ `ลบถาวร` ยืนยัน การลบรายวิชาถาวรรวมไฟล์ทุกเวอร์ชันและ PDF ผลตรวจ ทั้ง Drive และสำเนา Blob ที่ยังเหลืออยู่ จากนั้นจึงนำข้อมูลออกจากฐานข้อมูล กู้คืนไม่ได้ บัญชีหรือภาคเรียนที่ยังมีรายวิชา/เอกสารอ้างอิง รวมในถังขยะ ต้องจัดการรายวิชานั้นก่อนลบถาวร

งานลบเก็บความคืบหน้าในฐานข้อมูลและทำทีละไฟล์ หากบริการเก็บไฟล์ขัดข้องจะยังไม่ลบ metadata หรือแจ้งสำเร็จ สามารถกดลบถาวรซ้ำเพื่อดำเนินการต่อได้ โดยไม่เปิดให้กู้คืนรายการที่เริ่มลบถาวรไปแล้ว การบันทึก/ย้ายไฟล์ใช้ lease กันชนกับงานลบ และตรวจ hash ของแผนก่อนเริ่ม ไม่ลบทั้งโฟลเดอร์หรือเคลียร์ถังขยะ Drive ทั้งบัญชี ตัวรับไฟล์ `Code.gs` รุ่นที่รองรับ `permanent-delete-v1` ใช้สิทธิ์ Drive/UrlFetch เดิม โดยตรวจไฟล์ที่ผูกกับรายการและอยู่ในโฟลเดอร์โรงเรียนก่อนเรียก Drive API `files.delete` ([เอกสาร Google](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/delete))

- ลบบุคลากรได้เมื่อไม่มีรายวิชาหรืองานตรวจที่ยังใช้งานอยู่ และลบบัญชีตนเองไม่ได้ บัญชีที่ลบถูกปิดใช้งานและเพิกถอน session กู้คืนแล้วต้องเปิดใช้งานจากแก้ไขข้อมูล
- ลบรายวิชาแล้วหยุดรับส่งและออกจากคิวตรวจ/ลงนาม เอกสารเดิมยังดาวน์โหลดในคลังได้ กู้คืนได้เมื่อภาคเรียนและผู้รับผิดชอบพร้อม โดยเริ่มที่ปิดรับส่ง
- ลบภาคเรียนได้เมื่อไม่ใช่ภาคเรียนปัจจุบันและไม่มีรายวิชาที่ยังใช้งานอยู่ ให้ลบรายวิชาที่เกี่ยวข้องก่อน กู้คืนแล้วไม่เปลี่ยนภาคเรียนปัจจุบันอัตโนมัติ
- อีเมล รหัสบุคลากร และรหัสวิชา/ห้อง/เทอมเดิมยังสงวนไว้เพื่อเชื่อมประวัติ หากต้องการใช้รายการเดิมให้กู้คืนจากถังขยะ
- รหัสผ่านเดิมเป็น scrypt hash และเปิดดูย้อนหลังไม่ได้ ผู้ดูแลตั้งรหัสใหม่ได้ และดูรหัสที่เพิ่งตั้งในหน้าต่างผลสำเร็จเพื่อส่งให้ครู เมื่อปิดจะล้างค่านั้นจากหน้าจอ ไม่มีการเก็บรหัสผ่านข้อความปกติในฐานข้อมูล Snapshot Audit หรือ localStorage

จุดกดใช้เคอร์เซอร์รูปมือ และปุ่มที่ใช้ไม่ได้ใช้เคอร์เซอร์ห้ามกด การเข้าสู่ระบบ โหลดข้อมูล บันทึก อัปโหลด ดาวน์โหลด เปลี่ยนหน้า และเปิด PDF/Excel แสดงสถานะรอตามรูปแบบเว็บไซต์ โดยไม่มีการหน่วงคำขอจริงเพื่อให้เห็นป็อปอัพ

- รหัสผ่านใช้ scrypt พร้อม salt สุ่ม ไม่มีรหัสผ่านสำรองหรือค่าเริ่มต้นใน frontend
- session เป็น opaque token สุ่ม 256 บิต เก็บเฉพาะ hash ในฐานข้อมูล อายุ 8 ชั่วโมง cookie เป็น HttpOnly/SameSite=Strict/Secure บน HTTPS
- ออกจากระบบเพิกถอน session บนเซิร์ฟเวอร์ เปลี่ยนรหัสผ่านหรือระงับบัญชีเพิกถอน session ของบัญชีนั้น
- ตรวจ same-origin กับคำขอเปลี่ยนข้อมูล มีตัวนับจำกัดการลองรหัสผ่านที่เก็บในฐานข้อมูล
- ทุก mutation ตรวจสิทธิ์และสถานะเดิมบนเซิร์ฟเวอร์ ตรวจ `expectedRevision` กันการเขียนทับกัน และบันทึกประวัติใน transaction เดียวกัน
- ห้ามครูตรวจงานตนเอง ผู้ตรวจต้องตรงกับการมอบหมาย ผู้อนุมัติต้องเป็นคนละคนกับครูและผู้ตรวจ
- ไฟล์เก็บ private ใช้ upload token ที่จำกัด path/ชนิด/ขนาด/เวลา ดาวน์โหลดผ่าน API ที่ตรวจสิทธิ์
- ตรวจโครงสร้างพื้นฐาน XLSX, ไม่รับมาโคร, จำกัดขนาดขยาย ZIP และตรวจหัว/ท้ายไฟล์ PDF ก่อนผูกกับเอกสาร
- Production ใช้ PostgreSQL ที่ตรวจสอบ TLS certificate และ private Blob เท่านั้น

ข้อมูลธุรกิจรุ่นเริ่มต้นเก็บเป็น JSONB aggregate ในตาราง `pp5_state` ใช้ row lock ทำธุรกรรม เพื่อให้ลำดับงานและประวัติคงความสอดคล้อง เหมาะสำหรับเริ่มนำร่องโรงเรียนขนาดเล็ก เมื่อข้อมูลเพิ่มควรแยกตารางและทำ pagination ก่อนขยายการใช้งานหลายปี/หลายโรงเรียน Audit ใน API อ่านได้ 200 รายการล่าสุด แต่ข้อมูลทั้งหมดอยู่ในฐานข้อมูล

ต้องตั้งนโยบาย backup/restore, retention และการลบไฟล์อัปโหลดค้างกับบริการจริงก่อนเปิดวงกว้าง รุ่นนี้เก็บไฟล์อัปโหลดที่ยังไม่ส่งเป็น private และหมดสิทธิ์ใช้งานหลัง 30 นาที แต่ยังไม่มีงานลบวัตถุค้างอัตโนมัติ

## ตรวจสอบ

### การตอบสนองและแผนฟรี

API กำหนดให้ทำงานใน `sin1` ใกล้ฐานข้อมูล Neon และ Blob ที่สิงคโปร์ ใช้ภูมิภาคเดียวตามแผน Hobby การเปิดระบบ/รีเฟรชเรียก `session` เพียงครั้งเดียวและอ่านฐานข้อมูลหนึ่งครั้ง เพื่อส่งสถานะพร้อม snapshot ที่กรองสิทธิ์แล้ว ไม่ cache บัญชีหรือสิทธิ์ระหว่างคำขอ ส่วน `state` ยังคงต้องเข้าสู่ระบบและตอบ 401 สำหรับผู้ไม่มีสิทธิ์

หน้าเว็บแยกโหลดเมนูแต่ละส่วน และโหลดไลบรารีอัปโหลดเฉพาะเมื่อส่งไฟล์ PDF/Excel ที่เปิดในหน้าตรวจเก็บไว้ในหน่วยความจำระหว่างสลับแท็บ ไม่เก็บเอกสารลง localStorage/IndexedDB และคืนหน่วยความจำเมื่อออกจากหน้านั้น การเปิดไฟล์จาก Drive ครั้งแรกและการส่งไฟล์ยังต้องรอ Apps Script ตรวจต้นฉบับ จึงแยกจากความเร็วเมนูทั่วไป

ไม่ใช้ keep-alive หรือ polling เพื่อปลุกฐานข้อมูลทิ้งไว้ การเปิดครั้งแรกหลังบริการพักอาจช้ากว่าคำขอถัดไปตามข้อจำกัดแผนฟรี ตรวจเวลาด้วย `Server-Timing` ในคำขอ session/health/state และภูมิภาคจาก `x-vercel-id` โดยไม่บันทึกรหัสผ่าน คุกกี้ หรือเนื้อหาเอกสารใน log

- `npm test` — ทดสอบ API จริงกับ PostgreSQL ฝังตัวและไฟล์บนดิสก์ รวมการ restart, สิทธิ์ข้ามบัญชี, เวอร์ชัน, concurrent review, archive ZIP, logout และการจำกัดลองรหัสผ่าน
- `npm run check` — TypeScript สำหรับแอปและ API ที่ deploy
- `npm run build` — ตรวจ TypeScript และ build frontend
- `node --import tsx tests/create-fixtures.ts` — สร้าง PDF/XLSX ตัวอย่างที่ไม่มีข้อมูลส่วนบุคคลสำหรับทดสอบหน้าจอ

`src/App.tsx` ใช้ Sidebar, TopNavbar และหน้าจอเดิมใน `src/components/` โดย `src/context/AppContext.tsx` เป็นตัวเชื่อม API จริง ไม่สร้างข้อมูลตัวอย่างในเบราว์เซอร์ การอัปเดตนี้เพิ่มฟิลด์ที่เลือกใช้ได้ในข้อมูลเดิม ไม่รีเซ็ตฐานข้อมูลหรือบัญชีผู้ดูแล

## เมนูที่เชื่อมระบบจริงแล้ว

- ครู: ภาพรวม รายวิชา ส่งไฟล์คู่ ติดตามผล ส่งฉบับแก้ไข ประวัติเวอร์ชัน และคลังตามสิทธิ์
- ผู้ตรวจ: คิวที่ได้รับมอบหมาย ตัวกรอง อ่าน PDF/Excel จริง ข้อค้นพบ เกณฑ์ 4 ด้าน รับรอง/ส่งกลับ และ PDF แนบผลตรวจ
- ผู้บริหาร: คิวอนุมัติ ตัวชี้วัดจากไฟล์ที่อ่านได้ ลงนามทีละเล่ม/ยกชุด และดาวน์โหลดเล่มที่อนุมัติ
- ผู้ดูแล: บุคลากร/หลายบทบาท/รหัสผ่าน รายวิชา นำเข้า CSV คัดลอกข้ามเทอม จัดสรรผู้ตรวจ ปีการศึกษา ปฏิทิน/ขยายกำหนดส่ง ตราโรงเรียน ลิงก์ Drive คลัง ZIP ปลดล็อกยืนยันรหัสผ่าน และส่งออกประวัติ JSON

PDF ฉบับอนุมัติเพิ่มหน้าแนบท้ายภาษาไทยที่มีลายมือชื่อ ตราโรงเรียน และแฮช โดยไม่แก้ไฟล์ต้นฉบับ ไม่ใช่ใบรับรอง PKI จากหน่วยงานภายนอก การปลดล็อกเก็บหลักฐานอนุมัติเดิมใน `approvalHistory` ก่อนเปิดให้ส่งเวอร์ชันใหม่

Excel แสดงค่าที่บันทึกไว้ ไม่คำนวณสูตรใหม่ สถิติอ่านเฉพาะชีตที่พบคอลัมน์ `เลขที่`/`รหัสนักเรียน` และ `ผลการเรียน`/`เกรด`/`GPA` แบบชัดเจน (เกรดตัวเลข 0–4) ถ้าไม่พบจะแสดง “—” และยังดาวน์โหลดต้นฉบับได้ ควรทดลองแบบ ปพ.5 ของโรงเรียนจริงก่อนใช้สถิติประกอบการทำงาน

CSV ใช้หัวคอลัมน์ `course_code,course_name,grade_level,teacher_id` พร้อมคอลัมน์เสริม `reviewer_id,department,credit_hours,score_ratio` รหัสบุคลากรต้องมีอยู่ก่อน นำเข้าไม่เกิน 200 รายวิชาต่อครั้ง หากแถวใดผิดจะไม่บันทึกทั้งชุด

เมื่อเปิดการเชื่อมต่อ Drive แล้ว ไฟล์ใหม่จะตรวจสอบและคัดลอกเข้าโฟลเดอร์โรงเรียนโดยอัตโนมัติตามส่วนการเก็บไฟล์ด้านบน หากยังไม่เปิดเชื่อมต่อจะเก็บใน private Blob ไม่มีการบันทึกร่างก่อนส่งหรืออีเมลแจ้งเตือนอัตโนมัติ
